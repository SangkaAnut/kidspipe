## 1. Purpose, role, inputs and outputs

### 1.1 Role in the module chain

KiDS-1000 3x2pt order (`pipeline.ini:2`):
`sample_S8 sigma8toAs correlated_dz_priors one_parameter_hmcode camb wedges approximate_P_gm extrapolate_power load_nz_fits source_photoz_bias linear_alignment magnification_alphas projection add_intrinsic add_magnification bandpower_shear_e bandpower_ggl scale_cuts BOSS_like 2x2pt_like`.

This subsystem is everything between "3D power spectra and distances exist" and "tomographic angular spectra C_ell exist":

1. `load_nz` / `load_nz_fits` read tabulated n_i(z) once at setup, normalise them, and re-publish them to the datablock every evaluation.

6. `utils/magnification_alphas.py` only injects the magnification slopes alpha_i.
7. `utils/galaxy_bias.py` is a P_gm utility that is NOT referenced by any shipped ini or by `run_kcap.py` (grep over *.py/*.ini). In the 3x2pt chain P_gm comes from `modules/P_gm_approx/p_gm_approx_interface.py` instead.

## 2. Mathematical description

Notation: chi comoving distance in Mpc/h; a=1/(1+z); h=h0; Omega_m = `cosmological_parameters/omega_m`; ell is the (non-integer) multipole;
nu = ell + 1/2; D(z) a growth ratio defined in 2.6; f_K(chi)=chi for K=0, sin(sqrt(K) chi)/sqrt(K) for K>0, sinh(sqrt(-K) chi)/sqrt(-K) for K<0 (`utils.c:10-19`).

### 2.1 Comoving distance and spline conventions

chi(z) = h * D_M(z)[Mpc], taken from the 6000-point CAMB table by multiplying by h0 (`project_2d.py:538-541`).
`distances/a` is `1/(z+1)` computed by CAMB. Two interpolants are built (both GSL Akima splines, `gsl_wrappers.py:68`, default `spline_type=AKIMA`):

* a(chi): x = chi_i, y = a_i.
* chi(z): x = z_i, y = chi_i.

`chi_max` = max of the chi table = chi(z=6) (`project_2d.py:547`). z is reversed first if it is descending (`:533-536`); CAMB gives ascending, so no reversal.
The code supports curvature through K but camb_interface never sets K, and d_m is the radial (not transverse) comoving distance, so only K=0 is consistent.

### 2.2 n(z) loading and normalisation

`load_nz.py` (KV450):

* Each file is a 2-column text file z, n. For multiple files (space-separated `filepath`) the z columns must agree (`np.allclose`) and the n columns are stacked (`:25-37`).
* `histogram=True`: the file's z values are bin lower edges, so z <- z + (z[1]-z[0])/2 (`:58-64`). Assumes equal bin width. Note this edits z in place.
* If z[0] > 1e-8, one point (z=0, n=0) is prepended (`:66-72`). For KV450 after the histogram shift z[0]=0.025, so a 0 is always prepended: z = [0, 0.025, 0.075, ..., 5.975] (121 points; file has 120 rows, dz=0.05, z_lo=0..5.95; `data/KV450/nofz/Nz_DIR_z0.1t0.3.asc`).
* `upsampling>1` (default 1, unused in shipped configs): z_new = linspace(0, z[-1], len(z)*up); n sampled as a step function by `np.digitize` (`:74-81`).
* Normalise each bin: n_i <- n_i / trapz(n_i, z) with the trapezoid rule on the same non-uniform z (`:83-86`).
* The key `nz` written to the block is the count BEFORE the prepended zero / upsampling (`:41,45,95`), so `nz` can disagree with `len(z)`. Not used downstream.

`load_nz_fits.py` (KiDS-1000):

* Reads FITS extension `NZ_<NAME>` (falls back to `nz_<name>`), columns `Z_LOW, Z_MID, Z_HIGH, BIN1..BINn` (`:30-67, 97-110`). With `upsampling=1` (default) the sample points are Z_MID (`:45`), i.e. histogram heights are treated as point samples of a smooth curve.
* Same prepend of (z=0, n=0) if z[0]>1e-8 (`:15-27`), then trapz normalisation (`:73-75`).
* KiDS-1000 file (`bp_KIDS1000_BlindC_...Fid.fits`, measured by me): NZ_SOURCE has 119 rows, Z_MID = 0.025..5.925 step 0.05 (so 120 points after prepending 0), 5 bins; last z with n > 1e-6*max is 2.575, 3.875, 3.575, 3.025, 3.725 for bins 1-5. NZ_LENS (BOSS) has 79 rows, Z_MID = 0.005..0.785 step 0.01, 2 bins (80 points after prepending 0). No negative entries.
* Section written is `NZ_<NAME>`; projection finds it as `"nz_"+NAME`.

### 2.3 Photo-z shift (`photoz_bias.py`)

For each bin i with shift delta_i = `nofz_shifts/bias_i` (`per_bin=True` default; else `bias_0`):

* mode `additive`: n'_i(z) = n_i(z - delta_i) (`:56`). So the mean redshift moves by approximately +delta_i.
* mode `multiplicative`: n'_i(z) = n_i(z (1 - delta_i)) (`:54`).
* n_i is interpolated with `scipy.interpolate.interp1d(z, n, kind=interpolation, fill_value=0.0, bounds_error=False)` (`:51`). The query points are the same z grid, shifted. Outside [z_0, z_N] the result is exactly 0.
  * KV450: `interpolation = linear`. KiDS-1000: `interpolation = cubic` (scipy cubic = not-a-knot cubic spline through the points; negative overshoot is NOT clipped).
* Renormalise: n' <- n' / trapz(n', z) (`:60`).
* Optional `output_deltaz=True`: writes `delta_z_out/bin_i` = np.average(z, weights=n') - np.average(z, weights=n), a plain weighted mean over grid points, NOT a trapezoid-weighted mean (`:44-46, 62-64`). This is a diagnostic only.
* The shifts for KiDS-1000 are not sampled directly. `correlated_dz_priors` (`utils/correlated_priors.py:17-28`) computes bias = L p, where L = Cholesky(SOM_cov_multiplied.asc) (5x5, diag ~1e-4, i.e. sigma ~ 0.01) and p = `nofz_shifts/p_i` has prior N(m_i, 1) with m = L^-1 dz_mean (`runs/3x2pt/3x2pt_configs.py:14-21`, `priors.ini`). For KV450 `nofz_shifts/bias_i` are sampled directly with flat range [-0.1,0.1] (`KV450_values.ini:39-44`) and a priors file (`KV450_priors.ini`, [verified] now read: independent Gaussians with mean 0 and sigma = 0.039, 0.023, 0.026, 0.012, 0.011 for bins 1-5; the IA `A` Gaussian prior is commented out, so A is flat in [-6,6] with start value 0.0 in KV450 and 0.8 in the 3x2pt values file).
* [verified] The shift is applied ONLY to the source sample. In the KiDS-1000 chain `source_photoz_bias` has `sample = nz_SOURCE` (`pipeline.ini:95`); there is no second photoz_bias module, so the BOSS lens `NZ_LENS` bins are never shifted (consistent with spectroscopic lenses).
* [verified] `correlated_dz_priors` outputs `bias = L p` with `L = np.linalg.cholesky(cov)` (lower triangular, `correlated_priors.py:14,23`), and `p ~ N(m, 1)` with `m = L^-1 dz_mean` (`3x2pt_configs.py:17-19`), so bias ~ N(dz_mean, cov): the published `deltaz.asc` is used with the SAME sign as the code's `n(z - bias)`. The covariance matrix file prints diagonal entries 9.12e-5, 1.29e-4, 1.34e-4, 7.09e-5, 9.42e-5 (sigma 0.0096, 0.0114, 0.0116, 0.0084, 0.0097) and correlations up to ~0.31 (bins 2-3: 4.11e-5/sqrt(1.29e-4*1.34e-4) = 0.313). Whether `deltaz.asc` is defined with the same sign as the published KiDS-1000 convention remains open (8.4); the `deltaz.asc` file itself is not in the repo copy (find returned only `SOM_cov_multiplied.asc`).

### 2.4 Lensing efficiency kernel W(chi) and density kernel N(chi)

Redshift to comoving-distance density (`kernel.c:35-51, 177-200`):

    n_chi(chi) = n(z) dz/dchi = n(z) (1+z)^2 ( - da/dchi )        [z=1/a-1; units h/Mpc]

(da/dchi is the analytic derivative of the Akima spline a(chi); dz/dchi = -(1+z)^2 da/dchi.)

N kernel (`get_named_nchi_spline`, `kernel.c:177-200`): for every n(z) sample point z_i, chi_i = chi(z_i) (Akima chi(z)), N_i = n_i * (1+z_i)^2 * (-a'(chi_i)). The kernel is the Akima spline through (chi_i, N_i). It is NOT renormalised after the change of variable, so integral of N dchi equals 1 only up to the spline-vs-trapezoid mismatch (section 4).

W kernel (`shear_shear_kernel`, `kernel.c:90-170`), flat case, with the factor (3/2) Omega_m (100/c)^2 left out and applied later as `prefactor`:

    W(chi) = [ chi / a(chi) ] * ( 1 / Z ) * integral_{chi}^{chi_max} dchi' n_chi(chi') ( chi' - chi ) / chi'
    Z      = integral_0^{chi_max} dchi' n_chi(chi')

* n_chi inside the integrals is evaluated from an Akima spline of the n(z) samples (`spline_from_arrays`, `utils.c:21-27`) at z(chi')=1/a(chi')-1 and is set to 0 for z >= z_last (last tabulated z) (`kernel.c:43-47`).
* Both integrals are done with a FIXED 1024-point Gauss-Legendre rule (`NGLT=1024`, `gsl_integration_glfixed`): the normalisation Z over [0, chi_max], and, for each output node, the inner integral over [chi, chi_max] (`kernel.c:21, 104-105, 127, 153`). chi_max is the table maximum chi(z=6), so the GL nodes cover the whole z in [0,6] range, not only the support of n(z).
* Output nodes: 1024 uniformly spaced points chi_i = i * chi_max/1023, i=0..1023 (`:131, 140`). W(0)=0 (f_K(0)=0) and W(chi_max)=0 (empty inner integral). The result is stored as an Akima spline (`:166`).
* For K != 0: chi -> f_K(chi) in the outer prefactor, and the integrand factor (chi' - chi)/chi' becomes f_K(chi' - chi)/f_K(chi') (`w_of_chi_integrand`, `kernel.c:57`, with `chis` = integration variable chi' and `data->chi` = chi). Irrelevant for K=0.

The physical lensing kernel is then

    W_phys(chi) = (3/2) Omega_m (H0/c)^2 * W(chi),    (H0/c)^2 = (100/299792.4580)^2 (h/Mpc)^2

The scalar `shear_scaling = 1.5 * 100^2 / 299792.4580^2 * Omega_m` (`project_2d.py:75-79, 139-141`) = 1.668975e-7 * Omega_m (h/Mpc)^2 is applied once per W factor through `prefactor_power` (section 2.7). c = 299792.4580 km/s is the exact SI value.

CMB-kappa kernel (not used in KiDS, for completeness): W_K(chi) = [f_K(chi)/a] f_K(chi* - chi)/f_K(chi*), 1024 uniform nodes on [0,chi_max] (`kernel.c:266-298`).

### 2.5 Reduced kernels, growth, and the exact Limber integrand

For each spectrum the integrator does not use W,N directly but "reduced kernels" (`kernel.c:60-84`, `limber.py:130-134`):

    Wr(chi) = W(chi) D(chi) / sqrt(chi)      for 0 < chi < chi_D,max ;   Wr = 0 otherwise
    (spline = Akima through the original kernel's own node chi values)

where D(chi) is a growth-like function built FROM THE SAME 3D POWER SPECTRUM that is being integrated (`limber.py:111-128`):

    D(chi_j) = sqrt( P(k_g, z_j) / P(k_g, 0) ),  k_g = first grid k with k > 1e-3 h/Mpc   (index = np.where(k>k_growth)[0][0])
    and D = 0 wherever P(k_g, z_j) = 0; if P(k_g,0) ~ 0 it is replaced by 1.

[verified, extra detail] "P(k_g, 0)" is literally `p[0, growth_ind]`, i.e. row 0 of the z axis (`limber.py:121`); it is the z=0 spectrum only because every shipped P grid starts at z=0, and nothing checks this. `np.isclose(p_0, 0.0)` uses numpy's default atol=1e-8, an ABSOLUTE test in (Mpc/h)^3: for P_II ~ F^2 P_nl with F ~ 4e-3 A, P_II(k_g,0) drops below 1e-8 for |A| of order 1e-4 or smaller, after which D is no longer unity-normalised at z=0 (harmless analytically because D cancels in the integrand, but it is an arbitrary switch). For A>0 the IA spectra are negative (F<0), but the ratio P(z)/P(0) is still positive, so the sqrt is safe.
    Akima spline in chi_j = chi(z_j) for the z grid of that power spectrum. chi_D,max = chi(z_grid max) (=chi(6) here).

The C integrand (`limber.c:108-173`, `ext_order=0` is hard-wired at `limber.py:176`) is

    I(chi) = Wr_X(chi) Wr_Y(chi) P(k=nu/f_K(chi), chi) / ( chi D(chi)^2 ) * ( chi / f_K(chi) )^2

and is 0 if either Wr is 0, if either spline evaluation errors, or if the 2D spline evaluation errors (k or chi outside the grid).
Substituting Wr: the D factors cancel analytically, leaving

    C_XY(ell) = prefactor * integral_{chi_lo}^{chi_hi} dchi  W_X(chi) W_Y(chi) / f_K(chi)^2 * P_XY( k = (ell+1/2)/f_K(chi), z(chi) )     (K=0: / chi^2)

* "(ell+1/2)": yes, `nu = ell + 0.5` (`limber.c:134`). No other ell-dependent factor is applied (see QUIRK Q1).
* Integration limits: chi_lo = max of the two reduced kernels' first nodes, chi_hi = min of their last nodes (`limber.c:499-502, 554-555`). For W kernels these are 0 and chi_max; for an N kernel, chi_hi = chi(z_last of that n(z)) (=chi(5.975) KV450, chi(5.925) KiDS source, chi(0.785) lens).
* The 3D power is interpolated by a GSL 2D BICUBIC spline in (chi_j, ln k) of the linear-valued P (not ln P) (`limber.py:115`, `gsl_wrappers.py:117-136`). The data are passed as `p.T` flattened, so the x index (chi) runs fastest, matching GSL's expectation. Outside the (chi, ln k) rectangle the integrand is zero (no extrapolation).
  chi_j = chi(z_j) uses the z grid of the P section (CAMB: 100 points in [0,2) plus 50 in [2,6], reversed to ascending; `camb_interface.py:314-321`, `nz=150, zmid=2.0, nz_mid=100, zmax=6`).
* The 1D integral is adaptive `gsl_integration_qag` with the 61-point Gauss-Kronrod rule, `epsabs = limber_abs_tol (0.0)`, `epsrel = limber_rel_tol (1e-3)`, `limit = 4096` subintervals (`limber.c:15, 429`; defaults `project_2d.py:416-417`). If qag returns a nonzero status it falls back to a single 4096-point Gauss-Legendre rule on the whole interval (`limber.c:435-443`), warning once per process.
* The result is multiplied by `prefactor` (`:587`).
* Different ell are independent (OpenMP over ell, `:577`).

### 2.6 NLA intrinsic alignment model (`la_model`)

Fiducial method in BOTH shipped chains: `method = bk_corrected` (`pipeline.ini:103`, `KV450_fiducial.ini:145`, `run_kcap.py:545-548`).
Only the amplitude A is a parameter (`intrinsic_alignment_parameters/A`, prior [-6,6] in `*_values.ini`; the 3x2pt `values.ini` lists `a = -6.0 0.8 6.0`, key case-insensitive). There is NO eta (redshift power law), NO z0 pivot and NO luminosity scaling inside `la_model`.
Those exist as separate modules (`CSL/intrinsic_alignments/z_powerlaw/ia_z_powerlaw.py`, `luminosity_scaling/ia_lum_powerlaw.py`) that are not in either pipeline's module list. See 2.6.3.

#### 2.6.1 Constant C1 rho_crit

`compute_c1_baseline` (`linear_alignments.py:16-27`):

    C1 = 5e-14 h^-2 Msun^-1 Mpc^3
    C1_SI = C1 / 1.9891e30 kg * (3.0857e22 m)^3   = 7.3854e23  (h^-2 kg^-1 m^3)
    H = 100 * 1000 / 3.0857e22 s^-1  (the h^1 is implicit)
    rho_crit,0 = 3 H^2 / (8 pi G),  G = 6.67384e-11  = 1.87844e-26 h^2 kg m^-3
    C1 rho_crit = 0.0138731  (dimensionless; arithmetic by me from these constants)

This number (`C1_RHOCRIT`) is evaluated at import time. Its inputs are rounded: Mpc = 3.0857e22 m (vs 3.08568e22), G is the CODATA-2010 value.

#### 2.6.2 bk_corrected (fiducial) and the other methods

Inputs: z grid of `matter_power_nl`, k_h grid, P_nl[n_z, n_k], Omega_m, A. z0 = index where z == 0 EXACTLY (`np.where(z==0)[0][0]`, raises IndexError otherwise).
ksmall = argmin(k_nl) (lowest k on the grid, not a fixed value).

    D(z)   = sqrt( P_nl(ksmall, z) / P_nl(ksmall, z=0) )                        (linear_alignments.py:87)
    F(z)   = - A * C1rho_crit * Omega_m / D(z)                                   (:89)
    P_II(k,z) = F(z)^2 P_nl(k,z)                                                 (:94-95)
    P_GI(k,z) = F(z)   P_nl(k,z)                                                 (:98-99)

Equivalent to the standard NLA: P_GI = - A C1 rho_crit Omega_m / D(z) * P_deltadelta, with growth D(z) normalised to 1 today, amplitude NOT scaled by (1+z)/(1+z0)^eta nor by luminosity.
A>0 gives negative P_GI (negative GI contribution to the shear spectrum).
D is derived from the NON-LINEAR spectrum at the lowest k of the grid. P_II and P_GI inherit the full (z,k) grid of `matter_power_nl`, including the extrapolation to k=500 h/Mpc done by `extrapolate_power`.

The other methods (not used in the shipped chains):

* `bk` (`:50-76`): P_II(k,z) = f^2 P_nl(k, z=0) (z-independent), f = -A Omega_m C1rho; P_GI = f P_nl(z) / D(z). This is the original Bridle & King form with the missing (1+z)-type factor; the module description calls `bk_corrected` the fix.
* `linear` (`:109-136`): same as bk_corrected but uses the linear spectrum `matter_power` on its own grid.
* `krhb` (`:139-188`): P_II = f^2 P_lin(z=0), P_GI = f sqrt(P_lin P_nl_resampled) / D with a log-linear resampling of P_nl onto the P_lin k grid (restricted to P_nl's k range, `:164-171`) and back; uses `np.argwhere` with strict inequalities that cut the first/last point.
* `grid_mode=True` saves b_I(k,z), r_I(k,z) instead of power spectra (`interface:62-63`). Unused.

#### 2.6.3 Optional z-power-law (not in shipped chains)

`ia_z_powerlaw.py:16-48`: s(z,k) = ((1+z)/(1+z0))^alpha with z0 default 0.0 (`ia_section/z0`, optional) and alpha from `intrinsic_alignment_parameters/alpha`;
P_II <- P_II s^2, P_GI <- P_GI s, P_gI <- P_gI s. In-place edit of grids already in the datablock. To implement eta=alpha with pivot z0 you would insert this module after `linear_alignment`.

#### 2.6.4 Galaxy-intrinsic power (do_galaxy_intrinsic = T in the 3x2pt chain)

`linear_alignments_interface.py:70-77`:

    gm_k_max = 0.999 * k_gm[-1]
    P_gI(k,z) = P_GI(k,z) * P_gm(k,z) / P_nl(k,z)      restricted to k <= gm_k_max, on the k grid of P_gm

so P_gI = F(z) P_gm(k,z) (the matter-IA coupling F with the galaxy-matter cross spectrum replacing P_nl). The mask relies on P_gm sharing its k grid with the first part of the extrapolated P_nl grid (the assertions are commented out, `:74-75`). In the 3x2pt chain `approximate_P_gm` runs BEFORE `extrapolate_power` and `extrapolate_power` has `sections` unset, so P_gm is on the raw CAMB grid (kmax=20 h/Mpc, last point dropped by the 0.999 factor) while P_nl is extended to 500. The mask therefore crops P_gI to k <~ 20 h/Mpc.

### 2.7 Spectrum table: kernels, 3D power, prefactor

Let s = shear_scaling = 1.5 (100/c)^2 Omega_m = 1.668975e-7 Omega_m (h/Mpc)^2. `Spectrum.prefactor` (`project_2d.py:134-147`) = s^(prefactor_power) times the magnification factors; if prefactor_power==0 it returns exactly 1.0 (early return), so the magnification factor is never applied there (none of the magnification classes have prefactor_power 0).
Magnification factor for the position-type side (bin index b, 0-based): m_b = 2 (alpha_b - 1), alpha from `galaxy_luminosity_function/alpha_binned` (`:152-156`).

#### 2.7.1 Fast shear+IA combined kernel (KiDS-1000 cosmic shear)

`get_combined_shear_ia_spline` (`project_2d.py:633-669`):

    F_chi(chi_z) = P_II(k0, z) / P_GI(k0, z)      (k0 = FIRST k index; z-grid of the IA power)
    Q_i(chi) = W_i(chi) + F(chi) N_i(chi) / s

with F(chi) an Akima spline of F over chi(z) of the IA-power z grid. Asserts that P_II/P_GI at the first and last k agree to np.allclose defaults (scale-independent IA), else AssertionError. If P_GI[:,0] is all zero (A=0), Q = W.
With bk_corrected, P_II/P_GI = F(z) exactly, so s^2 Q_i Q_j P_nl = s^2 W_i W_j P + s F (W_i N_j + N_i W_j) P + F^2 N_i N_j P = GG + GI(ij) + GI(ji) + II. The integrator then runs once per bin pair (15 pairs) instead of three spectra.
Numerical detail: Q is a spline through nodes chi(z_n) of the n(z) grid (120 points), where W(chi) is evaluated from its Akima spline and added. It is NOT on the 1024 uniform W nodes. And the evaluation chi_hi for Q kernels is chi(z_last of the n(z)).
Since this path uses the same growth-reduced-kernel machinery, D is derived from `matter_power_nl`.
The IA amplitude A can no longer be changed without redoing the integrals (GG, GI, II are not separate).

#### 2.7.2 Adding partial spectra (`add_intrinsic`, `add_magnification`)

`add_intrinsic.py:62-99`, with `perbin=False` (default) so every A_i = 1 (the amplitude is already inside P_GI/P_II):

    shear_cl[i,j]  += shear_cl_ii[i,j] + shear_cl_gi[i,j] + shear_cl_gi[j,i]      for j<=i       (only if shear-shear=T; False in KiDS-1000)
    galaxy_shear_cl[i,j] += galaxy_intrinsic_cl[i,j]                                                      (position-shear = T)

where shear_cl_gi[a,b] has W of bin a and N of bin b (shear of a, intrinsic of b), hence the two GI orderings. If `shear_cl_ii_bb` exists, `shear_cl_bb` gets it (`:92-93`).
`add_magnification.py:34-38`: `galaxy_shear_cl[i,j] += magnification_shear_cl[i,j]` for all lens i, source j.
Final KiDS-1000 GGL: C_gG,ij = s Int N_i W_j P_gm/chi^2 + Int N_i N_j F P_gm /chi^2 + 2(alpha_i-1) s^2 Int W_i^lens W_j P_nl/chi^2.

### 2.9 Magnification slopes

`utils/magnification_alphas.py:11-14` simply writes the ini vector `alpha_binned` to `galaxy_luminosity_function/alpha_binned`. KiDS-1000 default `[1.8, 2.62]` (`run_kcap.py:971`; `pipeline.ini:108`), one per BOSS lens bin. The convention is that alpha is the slope of the cumulative number counts at the flux limit and the magnification contribution to delta_g is 2(alpha-1) kappa. The comment at `project_2d.py:89-91` states "factors of 2 alpha_i - 1" but the code is `2*(alpha-1)`. The code is the truth.

### 2.10 galaxy_bias.py (not wired in)

`utils/galaxy_bias.py` has three modes: `pk_gm` (assign measured P_gm per z-range to the matter z-grid, step / const / linear in z), `bias` (compute b(k,z)=P_gm/P_mm on the measured support, extend by 0 or constant in k and z, multiply by P_nl), `linear_bias` (P_gm = b1 P_nl).
It clips negative P_gm to 0 and writes `p_k` plus a `_cosmosis_order_p_k` marker (`:46, 110-118`). It is not in any module list of this repo; the 3x2pt chain uses `modules/P_gm_approx` (Lagrangian bias fit with `z_sep = 0.5`; bins merged at the z grid: `z<z_sep` uses low-z bias, else high-z; `p_gm_approx_interface.py:63-65`).

### 2.11 Reference algorithm (what you need to reproduce kcap's numbers)

1. chi_i = h * D_M,i (6000 pts, z in [0,6]); a_i = 1/(1+z_i). Akima splines a(chi), chi(z).
2. Load n_i(z) on its own z grid (prepend 0), trapz normalise. If photo-z: n_i <- interp(z - delta_i) with zero fill, trapz renormalise.
3. For each bin: N_i = n_i (1+z)^2 (-a'(chi)) at chi_i=chi(z_i). W_i on 1024 nodes via fixed 1024-pt GL (as 2.4) with Akima n(z).
4. IA: D(z) from P_nl at lowest k; F(z) = -A (0.0138731) Omega_m / D(z); P_GI = F P_nl; P_II = F^2 P_nl; P_gI = F P_gm (k <= 0.999 kmax_gm).
5. Per power spectrum: z_j -> chi_j, bicubic spline in (chi_j, ln k) of P; D(chi) from first k > 1e-3.
6. For each (A,B) pair and ell: integrate W_A W_B/ chi^2 P((ell+0.5)/chi, chi) over the overlapping chi support with G61 adaptive (rel 1e-3) and multiply by s^n and magnification factors.
7. Combine: KiDS-1000 shear = fast kernel; GGL = gm + gI + magnification.

### 3.2 Interpolation / extrapolation schemes

* 1D splines in C: GSL Akima (`gsl_interp_akima`, non-periodic) for a(chi), chi(z), n(z), W, N, reduced kernels, growth, F (`utils.c:23`, `gsl_wrappers.py:68`).
  * Derivative of a(chi) is the Akima spline's analytic derivative (`gsl_spline_eval_deriv`).
  * `gsl_spline_eval_e` outside the node range returns an error (EDOM); in the integrand this makes the integrand 0 (`limber.c:130`). `gsl_spline_eval` (non-_e) used in `n_of_chi` would return NaN on error with the handler off, but arguments are guaranteed in range (a in [a(chi_max),1]; z < z_last is tested).
* 2D: GSL bicubic (`gsl_interp2d_bicubic`) on (chi_j, ln k), values P (not ln P). GSL (EXTERNAL; from GSL's documentation, not verifiable here) estimates the derivatives with cubic splines along the grid lines. Out-of-grid -> error -> integrand 0.
* n(z): scipy `interp1d` linear (KV450) or cubic (KiDS-1000) for the photo-z shift; Akima for kernel building. Two different interpolants of the same data are therefore in play.
* Extrapolation: P(k) only through `extrapolate_power` (power law in k at high k). No z extrapolation anywhere (z beyond 6 not needed since kernel support is lower, but n(z) tail of a bin is truncated at z=6 inside the W integral).
* IA `krhb` method uses log-linear `np.interp` resampling (`linear_alignments.py:30-42`); unused.

## 4. Quirks, approximations, deviations from the textbook formula

* **QUIRK Q1 - shear C_ell is the convergence C_ell, and there are no (ell(ell+1)) or (ell+2)!/(ell-2)! factors.** The code returns the flat-sky Limber integral of kappa kernels with k=(ell+1/2)/chi (`limber.c:134-135, 151, 171`). There is no ell-dependent prefactor for shear versus convergence, nor for galaxy-galaxy lensing (the textbook full-sky factor sqrt((ell+2)!/(ell-2)!)/(ell+1/2)^2 -> 1 - O(1/ell^2)). Matters below ell ~ 10-30 only; KiDS scale cuts start at ell=100 for bandpowers (`pipeline.ini:167-168`). Downstream Hankel transforms assume this.
* **QUIRK Q2 - "reduced kernel" with growth factor from the same P being integrated.** Wr = W D / sqrt(chi), integrand divided by chi D^2. Analytically D cancels, numerically it does not exactly, because Wr is spline-interpolated on the kernel's nodes while D(chi) is spline-interpolated on the P z grid. For P_gm the growth is derived from P_gm itself, which contains the b1 step at z_sep=0.5 (INFERRED: the ratio P_gm(k_g,z)/P_gm(k_g,0) jumps by (b1_hi/b1_lo)^2-like factor at z_sep). Any Akima overshoot of D near that jump produces a small (INFERRED, unverified) error. The cleaner definition would be D=1 everywhere.
* **QUIRK Q3 - W normalised by numerical integral of the Akima-interpolated n(z) in chi, N normalised only by trapz in z.** Z (1024-GL in chi) and the trapz normalisation in `load_nz*` / `photoz_bias` differ at the sub-per-cent level for step-like n(z) interpolated with Akima. So int N dchi and the effective W normalisation are not identical. (INFERRED magnitude: up to ~1e-3, same order as the Limber tolerance.)
* **QUIRK Q4 - n(z) histograms treated as point samples.** `load_nz_fits` uses Z_MID as sample points and makes a smooth Akima curve through them (documented in `load_nz_fits/module.yaml`, "A proper solution... is in our roadmap"). `load_nz` with `histogram=True` shifts by half a bin. The photo-z shift then moves a cubic spline of that curve. A true histogram shifted by delta would give different numbers.
* **QUIRK Q5 - W integral covers [chi, chi(z=6)] with a fixed 1024-point rule regardless of the n(z) support.** For bins whose support is ~0.1-1.5 in z (~ 20-30% of chi_max) only ~300 nodes land in the support. Accuracy relies on n(z) being smooth. Each of the 1024 output nodes also re-evaluates the Akima n(z) spline inside the shifted GL nodes.
  * [verified, refinement] That node-count statement is right only for the LENS bins. Numbers for a flat LCDM h=0.7, Om=0.3 (astropy, my own check, not kcap output): chi(z=6) ~ 5.77e3 Mpc/h, node spacing ~5.6 Mpc/h. Lens n(z) support z in [0.2, 0.79] lies at chi/chi_max in [0.10, 0.33], i.e. W_LENS is nonzero on nodes 0..~341 and the inner GL integrand has support on only ~230-340 of its 1024 points. For the SOURCE bins W(chi) is nonzero from chi=0 up to chi(z_max,bin) (z_max = 2.575, 3.875, 3.575, 3.025, 3.725), i.e. ~72-88 % of the 1024 nodes (~730-880), and the inner GL integration support is the bin's own n(z) range. So the "only ~300 nodes" concern applies to W_LENS (magnification-shear), not to the cosmic-shear kernels.
* **QUIRK Q6 - shear_cl_gg is never written by add_intrinsic.** `add_intrinsic.py:52` sets `shear_shear_gg = sec_names['shear_shear']` (not `'shear_shear_gg'`), so `block[shear_cl,'ell'] = block[shear_cl,'ell']` and `block[shear_cl, bin_ij] = block[shear_cl, bin_ij]`: no-ops; the pure GG term is lost after addition despite the comment on `:78-79`.
* **QUIRK Q7 - autocorrelations store only the lower triangle**, contrary to the comment at `project_2d.py:700-703`.
* **QUIRK Q8 - Fast IA kernel resamples W on the n(z) nodes.** Q_i is built at chi(z_n) of the n(z) grid (120 points), evaluating the Akima W and Akima F there, then re-splined by Akima. This is a different interpolation from the separate GG/GI/II path and changes numbers at the 1e-3 level (INFERRED). W is also computed twice if both the F and the W kernel for the same sample are requested (`project_2d.py:638-644` vs `:613-614`).
  * [verified] The duplication is order dependent. `kernels_A` is filled in `SpectrumType` definition order, and for `fast-shear-shear-ia` the entry `F_SOURCE` is inserted before the special-cased `W_SOURCE` (`:394-404`); Python dicts iterate in insertion order, so `F_SOURCE` is loaded first, builds the 5 W splines into `kernels_A["W_SOURCE"]` (`:637-644`), and then the `W_SOURCE` entry is loaded and OVERWRITES them with 5 fresh identical builds (`:555-562`, `:611-614`). Net KiDS-1000 W builds: 2 (LENS) + 5 + 5 (SOURCE) = 12; 5 are redundant. The B side copies from A (`:573-579`), so no third build.
  * [verified] Latent failure: `get_combined_shear_ia_spline` always indexes `self.kernels_A["W_"+sample]` (`:637`). If the F kernel is requested only on the B side (e.g. `fast-position-shear-ia` alone, kernels "N F", without a `fast-shear-shear-ia` entry and without any spectrum having a W kernel of that sample on side A) this raises KeyError. Not triggered by the shipped chains.
  * [verified, INFERRED consequence] When A=0 exactly (`P_GI[:,0]` all zero, `:658-660`), the F kernel is the 1024-node `W` spline itself; for any A != 0 it is the node-resampled Q spline (120 nodes). C_ell(A->0+) and C_ell(A=0) therefore differ by interpolation error (plausibly ~1e-3, not measured) rather than continuously.
* **QUIRK Q9 - IA amplitude F(z) is not the "textbook" (1+z)/(1+z0))^eta L-dependent NLA.** It is -A C1 rho_crit Omega_m / D(z) only, with D from the non-linear spectrum at the smallest k, and Omega_m includes whatever CAMB's `omegam` contains (massive neutrinos included, INFERRED from CAMB naming `p.omegam`, EXTERNAL).
* **QUIRK Q10 - `bk` method keeps P_II z-independent** (the original BK 2007 form); `bk_corrected` is the CFHTLenS/Maccrann et al. form. Only the latter is used.
* **QUIRK Q11 - P_gI is built from P_GI * P_gm / P_nl**, i.e. the galaxy bias enters only through the measured/approximate P_gm (labelled "a bit of hack" in the code, `interface:70-72`). If P_nl crosses zero or P_gm and P_nl grids differ, the masks silently misalign.
* **QUIRK Q12 - magnification: `2*(alpha-1)`, no further z dependence.** Same alpha for all z in a bin. Magnification enters only in lens-source terms; lens-lens (magnification-position) and source-source magnification are not added to anything. The documentation string in the code mentions "2 alpha_i - 1".
* **QUIRK Q13 - growth in `la_model` is evaluated at the lowest k of the grid, in the NONLINEAR spectrum**, so non-linear/halofit amplitude at that k affects D (negligible at k~1e-4 but not a controlled definition). With massive neutrinos this D is scale-dependent at the lowest k (INFERRED).
* **QUIRK Q14 - photo-z interpolation with cubic spline can produce negative n(z)** (not clipped) and truncates shifted tails at z < z_0=0 or beyond z_last. After renormalisation by trapz, mass lost to truncation is redistributed.
  * [verified numerically] Replicating `load_nz_fits` + `photoz_bias` on the KiDS-1000 NZ_SOURCE bins (prepend 0, trapz-normalise, `interp1d(kind='cubic', fill_value=0)` at z-delta): for delta=0 the cubic reproduces the data exactly (min n = 0). For delta=+0.01 / +0.04 the most negative renormalised n(z) is -0.0030 / -0.0025 (bin 1), -0.0016 / -0.0018 (bin 2), down to -0.0003 / -0.0006 (bin 5), against peak heights of order 1-3; the integrated negative mass is <= 7.3e-4 of the unit norm (bin 1). So the negative-n(z) artefact exists but is a <=0.07 % effect. The reported `delta_z_out` equals the input shift to better than 0.1 % for bins 2-5 but is 0.00966 for delta=0.01 in bin 1 (3 % low, from the tail cut at z<0 and the grid-point-weighted mean).
* **QUIRK Q15 - the hard-coded zero-return outside the P grid.** For k = nu/chi below the lowest CAMB k or above 500 h/Mpc (or 20 h/Mpc for P_gm / P_gI) the integrand is exactly 0, with no warning. That is silent truncation of the integral.
* **QUIRK Q16 - integrand sets `result *= (chi/f_K)^2` described in the code as "a total hack"** (`limber.c:169-171`). For flat K=0 it is 1.
* **QUIRK Q17 - the 4096-point GL fallback** triggers only if qag fails; results from qag-success and fallback paths differ at O(tolerance), so the numerical noise of C_ell is of order 1e-3 in relative terms and can be discontinuous in parameters.
* Approximation: Limber with flat sky and (ell+1/2); no non-Limber correction (the `non_limber.c` and `ext_order>0` extended-Limber branches exist in the C files but `ext_order` is passed as 0, `limber.py:176`, and `non_limber.c` is compiled but not called by the Python interface).
* Approximation: IA only through NLA (linear tidal alignment from the non-linear matter power); no tidal torquing, no redshift evolution, no luminosity/colour dependence in the shipped chain.
* The bias between "intrinsic" and "shear": F_chi/N relation assumes C1 rho_crit is independent of galaxy sample. The same A is applied to all source bins (`perbin=False`, `add_intrinsic.py:71-75`).

## 5. Strengths

* The mathematics is textbook-clean and compact: every spectrum is the same Limber integral with a table of (kernel, kernel, P, prefactor); adding a new cross-spectrum is a few lines (`SpectrumType`).
* Careful h-unit convention: everything in Mpc/h and (h/Mpc)^3 avoids h bookkeeping in the integrand.
* The (ell+1/2) form is the better flat-sky Limber choice; the reduced kernels give better conditioned splines than raw W.
* GG+GI+II fast kernel: one integral per pair, a genuinely useful efficiency trick that is exact for scale-independent NLA.
* Kernel caching inside one evaluation: A/B kernels reused when identical by NAME (`load_kernels` copy at `:573-579`), `ell` OpenMP-parallel in C.
  * CORRECTED: the original text here claimed "P loaded once per section type". That is false. `Power3D` (`project_2d.py:13-29`) defines `__hash__` (hash of section name) but no `__eq__`, so equality is by identity, and every requested spectrum builds its own `Power3D` instance (`:452, :500`). `self.req_power` (a `set`) therefore keeps one entry per spectrum, and `load_power` (`:676-678`) re-reads, re-splines (2D bicubic) and re-derives the growth spline for each. [verified by running the same class pattern: a set of two instances with equal hash has len 2.] In the KiDS-1000 chain `matter_power_nl` is loaded twice (`fast-shear-shear-ia` and `magnification-shear`), `matter_galaxy_power` once, `galaxy_intrinsic_power` once: 4 loads instead of 3. For the KV450 chain (shear-shear, shear-intrinsic, intrinsic-intrinsic) there are 3 distinct sections, so no duplication there.
* Robust-ish integration: adaptive qag with a fallback integrator, zero outside domain rather than crash.
* Clear separation: n(z) loading (once at setup), photo-z shift (per evaluation), IA power (one pass), projection, adding terms. Each can be switched off via the ini.
* Magnification handled by a single multiplicative factor and a separate spectrum, so it is easy to toggle.
* Reasonable physical constants and the IA normalisation C1 = 5e-14 as in the literature (Bridle & King, Hirata & Seljak convention), cited in `module.yaml`.

## 6. Weaknesses and risks

Correctness / accuracy

* Fixed 1024-pt GL over the whole [0, chi(z=6)] range for W and its normalisation (Q5) and interpolation by Akima spline of a histogram-like n(z) (Q4): accuracy of W is set by interpolation rather than by quadrature. Reproducing kcap numbers to 1e-4 requires the same interpolation scheme (GSL Akima end conditions, EXTERNAL).
* Adaptive qag with epsrel=1e-3 produces C_ell with ~1e-3-level, parameter-discontinuous noise (Q17). Bad for Fisher/gradient/maxlike (kcap ships `3x2pt_maxlike_configs*`, INFERRED relevance) and a floor on any claim of sub-per-mille accuracy.
* Bicubic interpolation of P in linear value over a range of ~10 decades in k (not ln P) can ring and go negative; the resulting P is then used directly. A log-P interpolation would be safer (INFERRED, not tested).
* Q2: D derived from the integrated spectrum, including P_gm with a step in z at z_sep; kernel-vs-D interpolation mismatch.
* No curvature treatment in distances (radial vs transverse comoving) although a K switch exists.
* Q9: IA model is NLA with no z/luminosity evolution in the module list; users must know to add `z_powerlaw`. The `la_model` growth uses the lowest k and nonlinear P.
* `add_intrinsic` bug (Q6) loses GG; `perbin` IA amplitudes are read from `A1, A2...` while the 3x2pt values file defines a single `A`.
* Silent truncation outside the k range (Q15) and the P_gI mask relying on grid coincidence (Q11) with commented-out assertions.
* In-place `+=` on datablock arrays in `add_intrinsic`/`add_magnification`: re-executing a module twice in one block double-counts.
* Floating-point edge: the last W node `chi = 1023 * (chi_max/1023)` can exceed `chi_max` by one ulp; `gsl_spline_eval_e` then reports EDOM (EXTERNAL GSL semantics: x > xmax) and the whole kernel is discarded (`kernel.c:140-152`). CORRECTED/quantified [verified numerically]: for random chi_max in 5000-12000, (chi_max/1023)*1023 > chi_max in 3.0e-4 of cases (and < chi_max in 2.9e-4). If it triggers, `get_named_w_spline` returns NULL -> `NullSplineError` -> `project_2d.execute` returns 1 (non-fatal unless `fatal_errors=T`, `project_2d.py:734-741`), i.e. a spurious failed likelihood evaluation at ~0.03 % of cosmologies (chi_max = h * D_M(z=6) is a continuous function of the parameters). So "works in practice" is only true statistically.
* Several non-fatal assertions: `AssertionError` for scale-dependent IA in the fast kernel; `IndexError` when `z==0` is not exactly in the grid (`np.where(z==0)[0][0]`) or when no k > 1e-3.

Maintainability / portability

* Python side is Python 2/3 hybrid: `limber.py:8` uses `np.int` (removed in NumPy >= 1.24; CORRECTED wording: this raises AttributeError at import time of `limber.py`, not ImportError; the `c_int_array` it defines is never used afterwards); `project_2d.py:459` references `unicode` (NameError for non-str inputs under Python 3); `project_2d.py:519` calls `.append` on a `set` (AttributeError in the "no spectra requested" default path); `enum34.py` (790 lines) is vendored for an Enum that Python 3 provides; duplicate `get_reduced_kernel` definition (`limber.py:130-134`).
* Requires compiling `src/spec_tools.so` against GSL and `cosmosis/datablock/c_datablock.h` (`Makefile`); the Python wrapper loads GSL by `ctypes` and passes raw pointers (ctypes, no safety). The `limber_gsl_fallback_integrator` casts `ExtIntegrandData*` to `IntegrandData*` relying on identical leading layout (`limber.c:436`).
* All of this is wedded to the cosmosis datablock and C `names` constants (external). Hard-coded section names (`"matter_power_nl"`, `"galaxy_luminosity_function"`).
* Static per-thread workspaces sized by `LIMBER_NTHREAD_MAX=128` with `exit(1)` on overflow (`limber.c:518-521`).
* The shipped KiDS-1000 ini is auto-generated by `run_kcap.py` (1387 lines) with many string edits; the in-repo pipeline.ini is one snapshot.
* Magic strings in the option parser (hyphenated class names).

Performance (see section 7 for numbers)

* W kernels are O(n_chi^2) = ~1e6 n(chi) evaluations per bin (2 Akima evals + 1 Akima eval each) per likelihood call, even though only 5 source + 2 lens bins exist. The normalisation integral is repeated by every OpenMP thread (`kernel.c:123-127` is inside the `parallel` region).
* The same bicubic P lookup is repeated for every bin pair at every ell, although P(k_ell(chi), chi) is independent of the bin pair.
* Python-level loops over all `(i,j)` pairs and over ell blocks in C; GSLSpline `__call__` evaluates point by point in Python (used for F, W in `get_combined_shear_ia_spline`).
* W is built twice when a sample needs both `W_` and `F_` kernels.

## 7. Concrete efficiency opportunities

All timings below are order-of-magnitude estimates derived from operation counts in the source. No profile was run (the task forbade execution), so treat the speed-up factors as ESTIMATES.

1. **W(chi) in O(N) via cumulative integrals (largest, easiest win).**
   W(chi) = (chi/a) [ G1(chi) - chi G2(chi) ] / Z where G1(chi)=Int_chi^inf n_chi dchi', G2(chi)=Int_chi^inf n_chi/chi' dchi' (K=0). Both are reverse cumulative trapezoid/Simpson sums of n(z) over z or chi: cost O(n_chi) instead of O(1024 x 1024). Better still, do the integrals in z with the original n(z) samples (exact for piecewise linear n(z)) and avoid a(chi) derivatives and Akima entirely. Speed-up for the kernel stage 10^2-10^3 (1e6 integrand evaluations with 3 spline evaluations each vs ~1e3 operations per bin). Vectorise over all bins with a 2D array [n_bin, n_chi].
2. **Replace adaptive qag by a fixed vectorised quadrature on a precomputed chi grid.**
   Take ~300-600 chi nodes (Gauss-Legendre or log/linear Simpson over the common support) shared by all kernels. For each 3D spectrum compute P on the matrix [n_ell, n_chi] once (k = (ell+1/2)/chi), then all bin pairs follow from one contraction `C[i,j,l] = sum_c w_c A_i(c) B_j(c) G_l(c)` (`einsum`/BLAS; 5x5x400x500 = 5e6 MACs, ~ms). Compared with the present ~61x(5-30) integrand evaluations per (pair, ell) that each cost 3-4 spline evaluations plus a 2D bicubic evaluation, my estimate is a 20-100x reduction in projection time, with the added benefit of smooth, noise-free C_ell (derivatives w.r.t. parameters become usable). The accuracy must be checked once against a dense reference (e.g. rel. error < 1e-4 with 400-500 nodes for smooth kernels).
3. **Evaluate P(k,z) once per (spectrum type), not per bin pair.** Even keeping qag, reuse of P(chi,k) on the (n_ell x n_chi) grid saves a factor of n_pairs (15-45). 2D interpolation in numpy/scipy `RectBivariateSpline` on (z, ln k) with ln P (more robust) costs ~1e5-3e5 evaluations (~tens of ms).
4. **Separate GG / GI / II instead of the fast kernel when sampling A.**
   C = GG + A GI1 + A^2 II1 is an exact polynomial in A for NLA with the A-independent integrals. If the sampler moves A (and the photo-z shifts) while the cosmology is held fixed (e.g. a fast/slow parameter split in nested sampling or when A is a Gaussian-marginalised nuisance), only the polynomial coefficients need computing once. With KiDS-1000 style "fast" kernel every A change forces full reintegration. Savings equal the full projection time for each A-only step.
5. **Kernel cache across likelihood calls.** Lens kernels N_LENS, W_LENS depend only on the cosmology (distance table) and not on photo-z shifts or IA. In a nuisance-only move (photo-z, A, bias, alpha) they, and the whole cosmological P-grid, are unchanged. Source N_i, W_i only change with the shifts delta_i; per-bin updates are independent. Saves roughly 2/7 of kernel construction in every step and all of it for non-shift nuisance moves.
6. **Avoid double W construction** (F path builds W, then `load_kernel('W_...')` builds it again). Trivial fix; in the KiDS-1000 chain W_SOURCE (5 bins) is built inside the F kernel and again as `W_SOURCE`, plus 2 W_LENS builds: about 12 builds, 5 redundant (~40% of kernel time; INFERRED from the kernel list in `load_kernels`).
7. **Reduce unnecessary ell range / ell samples.** KiDS-1000 projects 400 points to ell=3e4; the bandpower window used downstream is ell 100..1500 for EE and nE, and xi_pm needs the Hankel integral over the full range. If only bandpowers are needed, n_ell could be halved in the cut range (INFERRED; depends on libbandpower and the apodisation; see open questions 8.5). For the GGL-only terms, ell above ~1500 is probably unused (INFERRED), so magnification-shear and galaxy-intrinsic spectra could be computed on a coarser or truncated grid, a ~2x saving on those 20 spectra.
8. **Numba/JIT of the integrand.** If the adaptive structure is kept, a numba kernel with precomputed spline coefficients (scipy `CubicSpline`/`Akima1DInterpolator`) removes ctypes overhead and Python-level loops over pairs; combined with item 2, no longer necessary.
9. **Let each thread do useful work in `shear_shear_kernel`**: the 1024-point normalisation integral is repeated redundantly by every thread (`kernel.c:123-127`); moving it before the parallel region saves T-1 repetitions of ~1e3 evaluations (small but free).
10. **Replace repeated GSL point-wise spline evaluations in Python** (`GSLSpline.__call__`, `project_2d.py:655-667`) by array evaluations; tiny but removes a Python loop of ~1e3 calls per bin.
11. **Use log P for the 2D interpolation and clip negative n(z)** to improve accuracy rather than speed (cheap; and avoids needing small tolerances).
12. **Shared dense chi-grid for N and W** ensures the product W*N and the Q kernel are consistent and removes the `chi(z_n)` irregular nodes.

* [verified] `KV450_fiducial.ini:124` spells the CAMB option `halofit_verion = mead` (typo). `camb_interface.py:94` only reads `halofit_version`, so the option is silently ignored and `camb.nonlinear.Halofit` gets its own default (EXTERNAL; likely `mead` in recent CAMB, not confirmed for the CAMB version kcap targeted). `BOSS_KV450.ini:136` has the same typo. * [verified] 3x2pt scale cuts relevant to the ell range actually consumed: `keep_ang_peee = 100 1500` and `keep_ang_pnee = 100 1070` (`pipeline.ini:167-168`) are overridden per lens/source pair by `keep_ang_pnee_i_j` = 100-300 (lens bin 1) and 100-600 (lens bin 2) (`pipeline.ini:184-193`; generated by `nE_scale_cuts` in `runs/3x2pt/3x2pt_configs.py:35-`).
