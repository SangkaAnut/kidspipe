Scope: how kcap wires CosmoSIS modules together (datablock model, module order), how parameters and priors are declared, how samplers are configured, how runs are generated programmatically, and how chains are post-processed.

## 1. Purpose, role, inputs and outputs

### 1.1 What this subsystem is

kcap is not a monolithic program. It is (a) a set of CosmoSIS modules (cosmosis-standard-library fork, COSEBIs/band-power C code, small Python modules in `utils/` and `modules/`), and (b) an *orchestration layer* made of `.ini` files plus Python generators. The orchestration layer consists of:

| Piece | File | Role |
|---|---|---|
| Pipeline description | `runs/config/*.ini` | CosmoSIS main ini: `[runtime]`, `[pipeline]` (module order, likelihood names, extra outputs), per-module `[sections]`, per-sampler sections, `[output]`. |
| Parameter file | `runs/config/KV450_values.ini` | Varied/fixed parameters with flat bounds. |
| Prior file | `runs/config/KV450_priors.ini` | Non-flat priors (Gaussians) layered on top of the bounds. |
| Run generator (current) | `utils/run_kcap.py` (1387 lines) | `K1000Pipeline` class: builds a *full* config dict for all KiDS-1000 / BOSS / Planck modules, then removes modules/keys/parameters according to a "run type" (EE, EE_nE, EE_w, ...), writes `pipeline.ini`, `values.ini`, `priors.ini`, git-status provenance files. |
| Run generator (deprecated) | `kcap/cosmosis_utils.py`, `kcap/twopoint.py` | Python wrappers (`CosmoSISPipeline`, `TwoPoint`) that assemble an ini from module objects and can run a pipeline in-process. README says the `kcap` package is "Deprecated" (`[K]/README.md`, repo-structure list). |
| Batch scripts | `runs/methodology/*.py`, `runs/3x2pt/*.py`, `runs/extended_cosmologies/*.py` | Loops that call `utils/run_kcap.py` via `subprocess.run` with CLI overrides (blinds, run types, scale cuts, start points). |
| Cluster scripts | `utils/create_slurm_scripts.py`, `runs/config/slurm/*` | Emit `sbatch` files that run `mpirun ... cosmosis --mpi <ini>`. |
| Chain post-processing | `utils/process_chains.py`, `utils/stat_tools.py` | Load CosmoSIS text chains into getdist, parameter-name mapping, PJ-HPD / HPD / quantile / std credible intervals. |
| MAP finder | `utils/maxlike/*` | Stand-alone Nelder-Mead maximiser using CosmoSIS `LikelihoodPipeline` (predates the CosmoSIS `maxlike` sampler). |
| Build | `build.py`, `CMakeLists.txt`, `conda_env.yaml` | Installs the CosmoSIS fork via pip from Bitbucket, then runs `cmake ..; make` for the C/Fortran modules. |
| MontePython wrappers | `montepython/*` | Deprecated; superseded by an external repo (`[K]/montepython/README.md`). Contains `.data` files only (likelihood settings), not code. |

### 1.2 CosmoSIS datablock model (exactly what the modules exchange)

- A **datablock** is a dictionary keyed by `(section, name)`. Both section and name are **lower-cased** on every access (`[CS]/datablock/datablock.cc:10,19,28,...` call `downcase`). So `A_s`, `a_s` and `A_S` are the same key. The text output headers are therefore lowercase (but `extra_output` entries are uppercased internally, `[CS]/runtime/pipeline.py:799`, and printed as `SECTION--NAME`; `process_chains.py` lower-cases everything on read, `[K]/utils/process_chains.py:526,612`).
- Values may be int, bool, float, complex, string, 1-D/N-D arrays. A **grid** (e.g. P(k,z)) is stored as three entries in one section: the two axes plus the 2-D array, written with `block.put_grid(section, "z", z, "k_h", k, "p_k", P)`. Two separate "namespaces" matter: the *options* datablock passed to `setup(options)` of each module (section `option_section` = the module's own ini section name) and the *run* datablock passed to `execute(block)`.
- Execution model (`[CS]/runtime/pipeline.py:599-697`): a fresh datablock is created for every parameter vector, holding all parameters as `block[section, name] = value` (varied from the sampler, fixed from the values file, `build_starting_block` lines 1074-1105). Then `module.execute(block)` is called in the order of `[pipeline] modules`. A non-zero status aborts that evaluation; the pipeline returns `None`, which becomes `like = -inf` (`pipeline.py:1350-1355`). Exceptions inside `run_results` are caught and also give a "zero likelihood" unless `debug=T` (`pipeline.py:1225-1232`).
- Likelihoods: each likelihood module writes `block["likelihoods", "<name>_like"] = ln L`. The pipeline sums the entries listed in `[pipeline] likelihoods` (`pipeline.py:1296-1318`). If the list is empty in the ini, they are auto-discovered from keys ending `_like` on the first run (`pipeline.py:1281-1294`; used by `run_kcap.py` which sets the list explicitly from `like_name`s, `[K]/utils/run_kcap.py:775-777`). `NaN` becomes `-inf`.
- Additional CosmoSIS bookkeeping: `data_vector` section (theory/data vectors written by likelihoods, used for mock creation and diagnostics); `priors` section (per-parameter log prior, `pipeline.py:1222-1223`).

### 1.3 Inputs and outputs of a run

Inputs: `pipeline.ini` (+ `values.ini`, `priors.ini`), data files (KV450: n(z) x5, 270x270 covariance, 18x16 data-vector file, c-term file; KiDS-1000: a "twopoint" FITS file with data+covariance and scale-cut tags, n(z) shifts covariance), optional BOSS / Planck / Pantheon data.
Outputs (text format, `[output] format=text`): one chain file with header line `#<col1>\t<col2>...`, rows of floats, and trailing `#key=value` metadata lines; for nested samplers a few more comment lines (see 2.6). Column order (CosmoSIS 3.12.1): varied parameters in values-file order, then `extra_output` entries, then sampler columns:
- metropolis: `prior`, `post` (`metropolis_sampler.py:21`)
- emcee: `prior`, `post` (`emcee_sampler.py:15`)
- multinest: `prior`, `like`, `post`, `weight` (`multinest_sampler.py:85`)
- maxlike: `prior`, `like`, `post` (`maxlike_sampler.py:7`)
`test` sampler writes no chain; with `save_dir` it dumps the whole datablock into a directory tree (one folder per section, one `.txt` per key, plus `values.txt`), used by tests and benchmarks (`[K]/tests/benchmarks/KV450_ccl.py:7-60`).

## 2. Mathematical description

### 2.1 Parameter vector, bounds, priors, posterior

Parameter file grammar (CosmoSIS `Parameter.parse_parameter`, `[CS]/runtime/parameter.py:265-303`; same grammar in `process_chains.get_sampled_params_and_ranges` which only keeps 3-value lines, `[K]/utils/process_chains.py:576-589`):
- `key = v` (1 number): fixed at v. Fixed parameters are still put in the datablock.
- `key = lo hi` (2 numbers): varied, start = (lo+hi)/2.
- `key = lo start hi` (3 numbers): varied, start in the middle slot. (kcap always writes 3-number lines; `run_kcap.py:197-220, 1238-1244`.)

- [verified] Typing detail (`parameter.py:283-292`): a one-number line that is integral AND parses as `int(line)` (e.g. `num_massive_neutrinos = 1`) is stored as a Python **int**; `omega_k = 0.0`, `w = -1.0`, `mnu = 0.06` stay floats. The 3-number grammar is `lo start hi` although the CosmoSIS docstring (`parameter.py:279-280`) says "start value, lower limit, upper limit" - the code (`return values[1], (values[0], values[2])`) is authoritative.
- [verified] Flat prior = `UniformPrior(lo, hi)` with `ln pi = -ln(hi-lo)` (`prior.py:238-250`); `parse_prior` splits on the first space and matches the type by lower-cased prefix (`prior.py:80-107`).

Ordering of the varied vector theta: order of sections and keys in the values file as parsed by `configparser`.

Priors (`[CS]/runtime/prior.py`):
- no entry in priors file and varied: flat on [lo, hi], log density = -ln(hi - lo) (`prior.py:241-251`).
- Gaussian entry `key = gaussian mu sigma` for a varied parameter is **truncated** to [lo, hi] (`parameter.py:67`, `TruncatedGaussianPrior`, `prior.py:331-376`):
  ln pi(x) = -(x-mu)^2 / (2 sigma^2) - ln(Phi(b) - Phi(a)) - 0.5 ln(2 pi sigma^2), a = (lo-mu)/sigma, b = (hi-mu)/sigma, -inf outside [lo, hi].
  The normalisation constants are *included*, so absolute values of ln post and the nested-sampling evidence are normalised quantities. (A 2020-era CosmoSIS may differ - UNVERIFIED-FORK.)
- Gaussian on a fixed parameter: ignored (delta function, `parameter.py:60-63`).
- Total: ln pi(theta) = sum_i ln pi_i(theta_i). `-inf` or NaN -> evaluation rejected before running any module (`pipeline.py:1208-1215`).
- Posterior: `ln P = ln pi(theta) + sum_k ln L_k(theta)`; ln L_k as written by each likelihood module. The KV450 likelihood is `ln L = -chi2/2` with **no** normalisation (no ln det C term).

### 2.2 Sampled-parameter transforms and derived parameters (formulas)

All implemented as tiny modules that run *before* or *after* CAMB:

1. A_s from ln amplitude (`utils/sample_ln_As.py:8-10`):
   A_s = exp(ln_1e10_A_s) * 1e-10.
2. One-parameter HMcode baryon model (`utils/one_parameter_hmcode.py:12-15`, defaults a_0=0.98, a_1=-0.12 from lines 5-6, fiducial ini lines 104-105):
   eta0 = a_0 + a_1 * A.
   CAMB then receives `HMCode_A_baryon = A`, `HMCode_eta_baryon = eta0` (`camb_interface.py:225-233`). With A = 3.13 (DM-only) eta0 = 0.6044 (CAMB's own default 0.603 is the DM-only pair in the 2016 model).
3. S8 as a derived parameter (`utils/derived_parameters.py:26-29`; alpha default 0.5 at line 18):
   S8 = sigma_8 * (Omega_m / 0.3)^alpha. CAMB's interface *also* writes `cosmological_parameters/S_8 = sigma_8(z=0) * sqrt(omega_m/0.3)` (`camb_interface.py:421`). Same formula, different key spelling (`S8` vs `S_8`).
   Optional `S_star = A_s/2e-9 * (Omega_m/0.3)^alpha` (line 36).
4. S8 as a *sampled* parameter (KiDS-1000 style; `utils/sample_S8.py`):
   Omega_m = (omch2 + ombh2)/h^2 if `omega_m` is not yet in the block (it is not, since CAMB runs later), else block value (lines 24-31);
   sigma8_input = S8_input / (Omega_m/0.3)^alpha, alpha=0.5 (line 33); if `S8_squared=T` then S8_input is first replaced by sqrt(S8_input) (lines 21-22) (used for the `S_8_2_input` variant).
   Stored as `cosmological_parameters/sigma_8_input`.
5. A_s from target sigma_8 (`utils/sigma8toAs.py`): runs its own CAMB transfer-only computation at a fiducial A_s = 2.1e-9 (line 28) with the same (H0, ombh2, omch2, omk, mnu, w, wa, ns); reionisation off; kmax = 1.2 **[corrected]** (this is assigned to CAMB `Transfer.kmax`, which is in Mpc^-1, i.e. k not k/h; `sigma8toAs.py:39`, option default `kmax=1.2` at line 8), `k_per_logint=5`, `high_precision=False`, `accurate_massive_neutrino_transfers=False`, single redshift 0, `DoLateRadTruncation=True` (lines 22-45). Then
   A_s = A_fid * (sigma_8_input / sigma_8_fid)^2   (line 54), because linear P(k) is proportional to A_s so sigma_8 is proportional to sqrt(A_s).
6. Correlated n(z)-shift priors (`utils/correlated_priors.py:11-26`, tested in `tests/test_correlated_priors.py`):
   delta_z = L p, with C_dz = L L^T (lower Cholesky of the covariance read with `np.loadtxt`), p = (nofz_shifts/p_1..p_5) i.i.d. N(m_i, 1). Output keys `nofz_shifts/bias_1..5`. The 3x2pt scripts set `m = L^-1 mu_dz`, `mu_dz` read from `deltaz.asc` (`[K]/runs/3x2pt/3x2pt_configs.py:11-19, 98-101`), so that `E[delta_z] = mu_dz`, `Cov = C_dz`. The sampling box is `p in [-5, 5]`, i.e. not centred on m.
7. Folded prior (`utils/sample_folded_prior.py:16-18`): x = fold + |x_folded - fold| with `fold` default 0.
8. Photo-z shift (`.../photoz_bias.py:51-60`), mode `additive`:
   n_i'(z) = n_i(z - delta_i) evaluated by `scipy.interpolate.interp1d(z, n, kind=interpolation, fill_value=0, bounds_error=False)`; renormalised so that trapz(n', z) = 1. Optional `delta_z_out/bin_i` = <z>' - <z> (trapezoid-free weighted mean: `np.average(z, weights=n)`). Interpolation is `linear` in the KV450 fiducial (ini line 141) and `cubic` in KiDS-1000 (`run_kcap.py:541`).
   Sign convention: positive delta moves the distribution to higher z (n'(z) = n(z - delta)).
9. IA amplitude: `intrinsic_alignment_parameters/A` is consumed inside `linear_alignment` (P_II ~ A^2, P_GI ~ A). `add_intrinsic` is then called with `perbin=False` so its per-bin amplitudes are 1 (`add_intrinsic.py:71-75`) and simply sums `C_GG + C_II + C_GI(i,j) + C_GI(j,i)` (lines 87-91).
   [verified] NLA `bk_corrected` (`linear_alignments.py:79-106`) uses only `matter_power_nl` (the lin grid is read but unused): `D(z) = sqrt(P_nl(z,k_min)/P_nl(0,k_min))` taken at the smallest tabulated k, `F(z) = -A * C1rhocrit * Omega_m / D(z)`, `P_II = F^2 P_nl`, `P_GI = F P_nl` (no (1+z)^eta, no luminosity scaling). `C1rhocrit = C1 * rho_crit0 = 5e-14 h^-2 Msun^-1 Mpc^3 / Msun[1.9891e30 kg] * (3.0857e22 m)^3 * 3H^2/(8 pi G)` (G = 6.67384e-11, H = 100 h km/s/Mpc) = 0.0138731 (computed). `Omega_m` is CAMB's `omega_m` (includes the neutrino density). Without `do_galaxy_intrinsic` (KV450 fiducial) only `intrinsic_power` (II) and `matter_intrinsic_power` (GI) are written.
   [verified] Limber projection (`project_2d.py`, `src/limber.c`): `nu = ell + 1/2`, `k = nu / f_K(chi)`, integrand `W_X W_Y / chi^2 P(k, z(chi))` with the shear prefactor `(3/2) (100/c[km/s])^2 Omega_m` per kernel (`project_2d.py:133-143`; chi is converted Mpc -> Mpc/h by `chi *= h0`, `project_2d.py:540-541`, which is why the prefactor uses H0 = 100); GSL QAG with `limber_rel_tol = 1e-3`, `limber_abs_tol = 0` (`project_2d.py:416-417`) and a fixed-table Gauss-Legendre fallback. The extended-Limber correction is disabled: `limber.py:175` hard-codes `ext_order = 0` (standard Limber, `K = 0`). `camb_interface.py:385` sets `D_M = comoving_radial_distance` (not the transverse distance), which is only right for flat models (omega_k = 0 is fixed in all kcap values files).

### 2.3 Likelihood wiring in the fiducial run (only what is needed to reproduce numbers)

(`utils/mini_2pt_like.py`; physics of binning is another document, but this is the node where orchestration choices enter.)
- n_bin = 5; 15 auto/cross pairs; each pair has 9 theta-bins for xi+ and 9 for xi- (270 data points). Cuts per pair: xi+ bins {7, 8}, xi- bins {0, 1, 2} (0-based; ini lines 192-193), leaving 13 per pair, 195 total.
- Data order is `montepython` (ini lines 194-195): loop `for i in range(5): for j in range(i,5):` pair (j,i) i.e. (1,1),(2,1),(3,1),(4,1),(5,1),(2,2),(3,2),...; each pair contributes `[xi+ (9), xi- (9)]` (mini_2pt_like.py:200-236). The data file has 18 rows (9 xi+ theta then 9 xi- theta) and 16 columns (theta + 15 pairs) with column index of pair (i>=j) = `j*(2n-j+1)/2 + (i-j)` (line 126).
- Covariance 270x270 (`cov_analytic_montepython_mcorr.txt`), rows/cols removed with the same cut indices (lines 84-95), then inverted once (line 99).
- Theory per pair: average of the 1024-point nicaea xi(theta) over each angular bin: `result_i = trapz(theta*xi, theta) / trapz(theta, theta)` using only grid points with `edge_i <= theta < edge_{i+1}`; edges are the 10 values in the ini (0.5 ... 300 arcmin, log-spaced with ratio (300/0.5)^(1/9) = 2.0357) converted to radians (ini lines 189-191; code lines 16-28, 60-65). Interpolate mode (`angular_binning_mode=interpolate`) would instead evaluate a log-theta spline at the data theta.
- Additive systematics: `xi+ += delta_c**2` in the `montepython` branch (line 226; the other branch, line 187, uses `delta_c` linearly - see QUIRK Q9), `xi+ += A_c^2 * c_plus(theta_bin)`, `xi- += A_c^2 * c_minus(theta_bin)` with `c_plus, c_minus` = columns 4 and 5 (`usecols=[3,4]`) of `KV450_ALL_c12_treecorr.out` (9 rows), after the same cuts (lines 101-109, 225-230).
- Multiplicative bias: **data** divided by `(1+m_i)(1+m_j)` with fixed `m = [-0.0128, -0.0104, -0.0114, 0.0072, 0.0061]` (lines 112-141, ini line 197); not a sampled parameter in the KV450 run.
- chi2 = (x - mu)^T C^-1 (x - mu); ln L = -chi2/2 (lines 238-245).
- [verified] additional behaviour of the KV450 likelihood: (i) in `integrate` mode the data theta values are NOT used for the theory (only the 10 edges); the trapezoid runs only over the 29-30 Hankel-grid nodes that lie inside each bin, so the integration limits are the first/last node inside the bin, not the edges (error O(d ln theta) = 2.4 % of a bin width in the weighting, small for smooth xi). The `InterpolatedUnivariateSpline(ln theta, xi)` is built in both modes (needs strictly increasing theta). (ii) The c-term arrays `xi_p_c, xi_m_c` have length 9 minus cuts and are the same for all 15 tomographic pairs (the file has 9 rows x 10 columns, `usecols=[3,4]` are the 0-based columns 3 and 4, e.g. 5.38e-7 and 1.04e-9 in the first row; column 1 holds the effective theta 0.7863 ... matching the data theta). (iii) The m-correction rescales only the **data** vector (lines 140-141); the covariance file `cov_analytic_montepython_mcorr.txt` is used unchanged ("mcorr" already in its name) and is inverted with `np.linalg.inv` once, with no Hartlap/realisation correction (also none in the KiDS-1000 `scale_cuts.py:89` path). (iv) `like_name + "_LIKE"` / `"_CHI2"` are written uppercase but the datablock lower-cases keys; the pipeline reads `likelihoods/<like_name>_like` for each name in `[pipeline] likelihoods` (`pipeline.py:1303-1305`). ### 2.4 Sampler algorithms and their configuration

Only the samplers kcap actually uses. Semantics below are CosmoSIS 3.12.1 (`[CS]/samplers/...`); kcap-fork additions are listed as such.

**metropolis** (`metropolis_sampler.py`, `metropolis.py`, `proposal/standard.py`)
- Config: `samples` (int, default 20000; fiducial 10000), `nsteps` (steps per call; fiducial 1), `covmat` (file; none in fiducial), `random_start` (F), `tuning_frequency` (-1 = no tuning), `exponential_probability` (0.333), `Rconverge` (-1 = off), `drag`, `oversampling` (5, fast/slow).
- Proposal: covariance C (default if no covmat and no hints: sigma_i = width_i/100, C = diag(sigma^2), `metropolis_sampler.py:204-217`); L = chol(C); move along the i-th column of `L R` (R a fresh random rotation re-drawn every ndim proposals), step length `2.4 * r`, with `r ~ Exp(1)` with prob. 1/3 else `r = sqrt(mean of min(ndim,2) squared N(0,1))` (CosmoMC style, `proposal/standard.py:5-43`).
- Accept if `post_new > post_old` or `post_new - post_old > ln U(0,1)` (`metropolis.py:284-285`). Prior bounds enter through `post = -inf`.
- Start: values-file start vector. No burn-in is applied by the sampler when `tuning_frequency=-1` (`tuning_end = 0`, all samples written). Burn-in is done in `process_chains.load_chain(burn_in=0.3)` by dropping the first 30 % of rows (line 660).
- With MPI each rank runs an independent chain written to `<filename>_<rank+1>.txt`.

**emcee** (`emcee_sampler.py`)
- Config in fiducial: `walkers=72` (`no_sys`: 32; `run_kcap` default `emcee_walker=80`), `samples=10000` (number of steps per walker), `nsteps=5` (steps per output block; `run_kcap` uses 5), `burn=0.3` (**not read by the sampler** - dead option), optional `covmat`, `a` (stretch scale, default 2.0), `random_start`, `start_points`.
- Start: ball of normalised radius 1e-3 around the start vector (clipped to [0.001, 0.999]) when nothing else is given (`emcee_sampler.py:75-82`). Move: Goodman-Weare stretch `StretchMove(a=2)`.
- Output row = (position, extra, prior, post) for every walker at every step; **chain is walker-interleaved**, not walker-sequential. `process_chains.load_chain` treats it as one long chain (burn-in cuts the first 30 % of rows, i.e. 30 % of the steps of all walkers).

**multinest** (`multinest_sampler.py`, ctypes into `libnest3`)
- Likelihood passed to MultiNest = `results.like` (pure likelihood). Prior enters through the hypercube transform `denormalize_vector_from_prior` (`pipeline.py:953-962`): each unit-cube coordinate u maps to x with CDF_prior(x) = u (flat -> linear; truncated Gaussian -> bisection of the truncated normal CDF on [-20,20]/[a,b], `prior.py:547-583`). Hence priors with bounds and Gaussians are treated exactly.
- Per-sample outputs: `prior` (log), `like`, `post` (= prior + like) and `weight` (importance weight when `ins=True`).
- Options and defaults (`multinest_sampler.py:104-131`): `max_iterations` (required), `live_points` (required), `resume` F, `multinest_outfile_root`, `update_interval` 200 (kcap uses 20), `random_seed` -1, `ins` (importance nested sampling) **True by default** (the fiducial ini mentions `ins=F` only in a comment, line 65), `efficiency` 1.0, `tolerance` 0.1, `log_zero` -1e6, `mode_separation` F, `constant_efficiency` F, `max_modes` 100, `wrapped_params` "".
- Fiducial KV450 ini: `live_points=250, efficiency=0.8, tolerance=0.1, constant_efficiency=F, resume=F, max_iterations=100000` ("quick run", ini comments claim ~140k evaluations, ~9k independent samples, lines 31-38); "KV450 fiducial set up" in comments (lines 60-65): `live_points=1000, efficiency=0.3, tolerance=0.5, ins=F`.
- `run_kcap.py` defaults (`create_sampling_config`, lines 817-824): `live_points=250, efficiency=0.8, tolerance=0.1, resume=T, update_interval=20, max_iterations="1000000"`; the batch scripts override to `efficiency=0.3`, `tolerance=0.01`, `live_points=500` (`runs/3x2pt/3x2pt_configs.py:28-31`, `runs/methodology/create_main_chains_configs.py`). `BOSS_KV450.ini`: `live_points=1000, efficiency=0.3, tolerance=0.5, resume=T`.
- Output file ends with `#nsample=<n>`, `#log_z=...`, `#log_z_error=...`; the file contains all rows from the last dump but only the last `nsample` rows are the final posterior samples (`process_chains.load_nested_sampling_file`, lines 557-570).
- Evidence reported = INS log-evidence if `ins=True` else standard (`multinest_sampler.py:223`).

**dypolychord / polychord** (`KV450_no_sys.ini:28-39`, `BOSS_*.ini`)
- Options visible only in ini files: `do_dynamic_nested_sampling=F, base_dir, file_root, live_points=50 (no_sys; BOSS_KV450 uses 300), nlive_const=50, ninit=30, precision_criterion=0.1, dynamic_goal=1.0, feedback=3`, with `fast_slow=T` in `[pipeline]` for no_sys (line 16) and `fast_fraction=0.3` in the `[dypolychord]` section of BOSS_KV450 **[corrected]**: `BOSS_KV450.ini` actually has `sampler = multinest` and `fast_slow=F` (line 22), its `[dypolychord]` block (`live_points=300`) is unused; `BOSS_only.ini` has `sampler = metropolis` and `fast_slow=T`; `KV450_no_sys.ini` has `fast_slow=T` (line 16) with `dypolychord`. The `dypolychord` sampler is a kcap-fork addition; its source is NOT available in this reference (not in `[CS]/samplers`). Stock `polychord` options (3.12.1 `polychord_sampler.py:114-147`): `live_points` 100, `num_repeats` 0 (=> 5*ndim in PolyChord), `tolerance` 0.1, `fast_fraction` 0.5, `boost_posteriors`, etc.
- Fast/slow in CosmoSIS: `fast_slow=T` makes the pipeline analyse parameter dependence by module and cache the output of all modules before the first one that depends on a fast parameter, restarting from that point when only fast parameters change (`pipeline.py:97-316, 599-650`). [verified] In 3.12.1 `first_fast_module` is optional (`pipeline.py:483-496`) but the **metropolis** sampler refuses `fast_slow=T` unless it is set manually (`metropolis_sampler.py:60-63`); no kcap ini sets `first_fast_module`, so `BOSS_only.ini` (metropolis + `fast_slow=T`) would raise under 3.12.1 (the 2020 fork may have behaved differently - UNVERIFIED-FORK). The slow-subspace cache keeps at most 3 entries (`cache_size_limit=3`, `pipeline.py:98`).

**maxlike** (kcap `run_kcap.py:837-842` + CosmoSIS `maxlike_sampler.py`)
- Optimiser works in the unit hypercube: `u = (x - lo)/(hi - lo)` (`parameter.py:156-166`), returns +inf outside [0,1]^n, objective = `-ln post` if `max_posterior` else `-ln like` (`maxlike_sampler.py:36-46`). Default method `Nelder-Mead`, `tol` = `tolerance` (1e-3 default), `maxiter` default 1000, via `scipy.optimize.minimize(..., method, jac=False, tol=tolerance, options={maxiter, disp})` (lines 76-78). `bobyqa` option uses `pybobyqa` with `rhobeg=0.1, rhoend=tolerance, seek_global_minimum=True`.
- Start: `start_estimate()` (previous sampler's peak, else values-file start). The batch scripts supply a start via `--set-parameters sec key "nan <start> nan"` which replaces only the start (`run_kcap.set_parameter_range`, lines 205-216: `nan` min/max keep the old bounds).
- kcap sets (in `[maxlike]` of generated ini): `method=Nelder-Mead`, `tolerance=1e-3` (CLI scripts use 0.01 / 1e-4 / 1e-5, 0.0001 ...), `maxiter=max_iterations` (3000 via scripts, otherwise "1000000"), `max_posterior=T` by default (`run_kcap.py:799`: `max_posterior=True`), `output_steps=T`, `flush_steps=1`. Extra solver keys passed through (`step_size`, `grad_eps`, `gtol`, `ftol`, `lbfgs_maxcor`, `output_covmat`, `maxlike_method` mapped to `method`) are consumed by the **fork's** maxlike sampler, which supports Powell / L-BFGS-B variants (`runs/3x2pt/3x2pt_maxlike_configs_alt_solvers.py:158-170`); their implementation is not in the repo/3.12.1 (UNVERIFIED-FORK). Note in `create_main_chains_configs.py` the line `"--sampler-config", "max_posterior", ''` yields falsy -> `"F"` (QUIRK Q16).
- `output_covmat` from `result.hess_inv` (BFGS-type solvers), de-normalised by `C_ij * range_i * range_j` (`pipeline.py:998-1018`).

**Stand-alone `utils/maxlike/maxlike_cosmosis.py`** (Asgari/Marika script; README: "uses Nelder-Mead")
- Build `LikelihoodPipeline(Inifile(ini))`; start from the max-`post` (or max-`like` with no `--max_post`) row of a given MultiNest chain whose first n_vary columns are assumed to be the varied parameters in order (line 94) else from the values-file start vector; operate in the unit cube; objective returned `= -2 * ln post` (with `--max_post`) or `-2 ln like`; `+inf` outside cube; `scipy.optimize.minimize(method='Nelder-Mead', options={maxiter (default 1600, CLI), xatol: 1e-3, fatol: 1e-2, adaptive: True})` (lines 230-231). Appends each step as a row if `-s`. Final lines: `# post_min=<fun/2>`, `# n_eval`, success/failure message. Optionally writes a new values file with the best fit as start via `pipeline.create_ini` (lines 288-290) and a priors file whose Gaussian means are replaced by the best-fit values (lines 291-321; this only handles Gaussian entries and assumes the whitespace layout `key = gaussian mu sigma`).

**test sampler** (`test_sampler.py`): evaluates the pipeline once at the values-file start vector, prints prior, likelihood, posterior, optionally `save_dir=%(OUTPUT_DIR)s/output_%(RUN_NAME)s` (ini line 85) and `fatal_errors=T`. `run_kcap.py` writes `{"save_dir": <chain_dir>/data_block, "fatal_errors": "T"}` (line 834).

### 2.6 Post-processing of chains - formulas

**Loading (`process_chains.load_chain`, lines 603-710).**
- Header = first line minus leading `#`, tab-split (cosmosis) lower-cased (falls back to space split if only one token). Each name is mapped through `parameter_dictionary` (lines 292-513) to cosmomc-style names + LaTeX labels; unknown names are kept with a warning.
- Columns whose cosmomc-mapped names equal those of the dictionary keys `weight` and `lnlike` (cosmomc names `weight` and `loglike`, i.e. CosmoSIS `weight` and `like`; **[corrected]**: the cosmomc name is `loglike`, `process_chains.py:498-501, 508-510`) are split off as weights/loglikes (lines 643-652). `prior`/`post` columns are kept as ordinary "parameters" named `logprior`/`logpost`.
- Nested-sampling detection: the last 3 lines must match `^#([a-z_]+)=([0-9\.\-]+)`; then `chain = loadtxt(...)[-nsample:]`, with `log_Z`, `log_Z_err` attached (lines 557-570). Anything else (metropolis, emcee, maxlike) goes to the MCMC branch, burn-in `int(n*0.3)` if float in (0,1) else int rows (lines 658-668).
- Ranges for getdist are read from the values file (`get_sampled_params_and_ranges`, only 3-number lines) so KDE boundary corrections work; `extra_ranges` merge on top.
- `getdist.MCSamples(samples, weights, loglikes, names, labels, sampler="nested" or None, ranges)`.

**Credible intervals (`utils/stat_tools.find_CI`, lines 9-109)**, target coverage default 0.683:
- `std`: n_sigma = -Phi^-1((1-cov)/2); CI = mean +- n_sigma * sigma with weighted mean and weighted sample covariance (`np.cov(aweights, ddof=1)`); point estimate = mean (lines 112-160).
- `tail CI`: CDF built from weighted samples by piecewise-linear interpolation (`create_interpolated_cdf`, lines 355-387: duplicate sample values merged by summing weights; CDF = cumulative weight with first value subtracted so it starts at 0; `InterpolatedUnivariateSpline(k=1, ext=3)`), solve `cdf(l) = (1-cov)/2`, `cdf(u) = 1-(1-cov)/2` with `brentq` on [min, max]; point estimate = CDF root at 0.5 (lines 163-230).
- `HPD` (marginal highest posterior density): weighted Gaussian KDE (`scipy.stats.gaussian_kde`, `bw_method="silverman"`, weights); marginal MAP via `minimize_scalar` (Brent, bracket (min,max)); find level lambda in (0, p_max) such that the integral of KDE over {p >= lambda} (between the two roots on either side of the MAP, clipped to [min,max] if lambda is below the density at the sample edges) equals cov, by `brentq` (lines 234-345). [verified] The weighted `scipy.stats.gaussian_kde` has no boundary correction (no reflection at the prior edges), so HPD intervals of parameters piled up at a prior bound are biased; the flag below is the only safeguard. Flag `prior_edge_hit` if `p(min)/p_max > 0.1` or `p(max)/p_max > 0.1`.
- `PJ-HPD` (projected joint HPD, Joachimi et al. 2021, the KiDS-1000 headline method): sort samples by decreasing joint ln post; for n = 2..N take the n best joint samples, form the 1-D range [l_n, u_n] = [min, max] of this parameter over those samples, coverage_1d(n) = sum of weights of **all** samples with x in [l_n, u_n]. Stop at first n with coverage >= cov. Method "interpolate" (default): keep inner limits (last n with coverage < cov, coverage_inner) and outer limits (smallest l, largest u seen after crossing); once both sides have separated, solve for t in [0,1]
  `coverage_inner + CDF_low(l(t)) + CDF_up(u(t)) = cov` with `l(t) = l_outer(1-t) + l_inner t`, `u(t) = u_outer(1-t) + u_inner t`, CDF_low(x) = weight in (x, l_inner], CDF_up(x) = weight in (u_inner, x] (piecewise-linear interpolants, `ext=3` constant extension), by `brentq` on [0,1] (lines 513-532). Point estimate = the joint-posterior MAP sample's value of this parameter (`samples[sort_idx[0]]`). `twosided=True` default; if the MAP is at the sample edge, falls back to one-sided with a warning. Other methods: `expand`, `expand symmetric`, `expand minimal` (SLSQP, ftol 0.05).
  QUIRK: `process_chains.find_MHPD_CI` (older copy) starts the loop at i=3, `stat_tools` at i=2 (line 496) - identical logic otherwise.
- weights: nested sampling `weight` column; MCMC: None -> 1/N.

## 5. Strengths of this subsystem

1. The module/ini architecture isolates each physical step behind a stable (section, key) interface; swapping Halofit/HMcode, adding IA or magnification modules, or changing likelihoods needs only an ini edit. The run-type table in `K1000Pipeline` encodes the whole KiDS-1000 analysis family (EE, EE_nE, EE_w, nE_w, ...) as set operations on one master config, which makes variants reproducible and diff-able.
2. Runs are self-contained and provenance-rich: data files are copied into the run directory, `command.sh` and several `git status` snapshots are written (`run_kcap.py:30-54, 1375-1386`).
3. Parameter handling is simple and explicit: bounds in one file, non-flat priors in another, with exact truncated-normal normalisation and exact inverse-CDF hypercube transforms for nested sampling. Derived parameters (S8, sigma_8, A_s, theta_MC, delta-z shifts) are exported via `extra_output`, so chains are directly publishable.
4. Clever, cheap parameter reparameterisations: ln A_s or S_8 as the sampled amplitude parameter, one-parameter baryon model, and the Cholesky decorrelation of the n(z)-shift prior (unit Gaussians sampled, correlated shifts generated) which makes nested sampling efficient and keeps the prior analytic.
5. Several samplers are supported through the same config (metropolis, emcee, MultiNest, (dy)PolyChord, maxlike, test) with MPI parallelism in one command (`mpirun cosmosis --mpi ini`); fast/slow parameter splitting is available to exploit cached CAMB runs.
6. Post-processing is statistically careful: PJ-HPD credible intervals avoid projection effects and prior-volume artefacts; the code handles weighted samples (nested) and duplicates, and provides alternative interval definitions for comparison.
7. Numerical settings (redshift grid with finer sampling at z < 2, high-k extrapolation, 400-point ell grid, 1024-point Hankel grid) are explicit in the ini and have been used for published results.

## 6. Weaknesses and risks

Correctness
- Silent option typos (Q1) are accepted because CosmoSIS ignores unknown keys; the fiducial config's physics depends on the installed CAMB version. The same applies to dead options (`burn`, `max_posterior=''`).
- Inconsistent definitions between the sampled amplitude proxy (S_8_input via Omega_m without neutrinos and an auxiliary low-precision CAMB call) and the reported derived S_8 (Q11, Q12). Reproducing "numbers" requires reproducing the proxy.
- Likelihood branch inconsistency (Q9), `theta_max` bug (Q3), stale-index bug in chain loader (Q18), unclear getdist sign (Q19).
- Dependence on hidden state: Python dict insertion order defines module order; shared mutable dicts; mutating `file` key (Q5).

Accuracy
- Nelder-Mead MAP in a 12-20 dimensional unit hypercube with loose tolerances (`xatol 1e-3, fatol 1e-2`) is prone to premature convergence and to local optima; the repository itself contains scripts testing Powell and L-BFGS-B and 36 starting points for the 3x2pt MAP **[corrected]**: they are the 36 highest-`logpost` samples of an existing MultiNest chain, not random starts (`n_start_point = 36` at `3x2pt_maxlike_configs.py:22`; selection `logpost_sort_idx[:n_start_point]` at line 83), which indicates MAP robustness was an issue.
- The default metropolis run (diagonal covmat of 1 % of widths, no tuning, 10k samples) will not converge in 14 dimensions; the fiducial ini is a demonstration setting, not a production one.
- The evidence/posterior depend on MultiNest efficiency/tolerance choices that differ between files (0.8/0.1 vs 0.3/0.5 vs 0.3/0.01).

Maintainability and portability
- The CosmoSIS runtime is not in the repo; it comes from a Bitbucket fork pinned only by `>=0.0.10`; the dypolychord sampler and fork-specific maxlike options cannot be inspected here. Python/CAMB/CMake version drift breaks the build (Q21). The conda env is unpinned.
- Many generated scripts hard-code absolute or relative paths to unavailable data (`../Cat_to_Obs_K1000_P1`, `../kcap_boss_module`, `../HMx`, `../ReACT`), cluster modules and a personal email.
- Large dead/deprecated code (`kcap/` package, `montepython/` data, commented blocks) coexists with active code; no unit tests for `run_kcap.py` (tests cover correlated priors, HMcode, comparisons against CCL/MontePython; [verified] only `tests/test_hmcode.py` contains assertions - `np.allclose` with rtol 3e-3 for z<2 and 1.5e-2 for z>=2 between `meadcb` and CAMB - while `test_pipeline_against_CCL*.py` are plotting scripts with no assertions, so they give no pass/fail reference for a clone).
- ConfigParser round trip lowercases keys and applies `%` interpolation; module options are stringly typed (booleans as "T"/"F").

Performance
- Every likelihood evaluation runs CAMB (transfer functions + non-linear P), a second CAMB call in `sigma8toAs` (K1000 setup), two heavy numerical transforms (Limber projection with 400 ell, Hankel transform with 1024 theta per spectrum pair) and writes/reads large arrays through the C datablock (copying P(k,z) of ~150 z x O(10^3) k several times). Nuisance parameters (A_IA, delta z, delta c, A_c) that only affect late modules are still handled by the generic pipeline unless `fast_slow=T` is used (only in `KV450_no_sys.ini` and `BOSS_only.ini`; `BOSS_KV450.ini` has `fast_slow=F`; and under CosmoSIS 3.12.1 metropolis would additionally need `first_fast_module`).
- Nested sampling cost: ini comments quote ~140k evaluations for 250 live points, ~350k for 500, ~1M for the "mega-run" (lines 36-58); the KV450 slurm script requests 40 MPI tasks for 2 days (`runs/config/slurm/cuillin_KV450.sh`), BOSS run 80 tasks. Wall-time per evaluation is not recorded anywhere in the repo.

## 7. Concrete efficiency opportunities (estimates, not measurements)

All speed-ups are order-of-magnitude estimates from the structure of the code; the repo contains no timing data.

[verified, measured in this pass; CAMB 1.5.8, Python 3.12, WSL2, this machine, 3 repeats, not a rigorous benchmark] Cost split of one `camb` module call with the fiducial grid (150 z, kmax = 20 Mpc^-1, ~195 k, `mnu=0.06`, `NonLinear_pk`), cosmology H0=70, ombh2=0.0225, omch2=0.13, n_s=0.97:

| step | mead2020 (CAMB default) | mead (=2016) | takahashi |
|---|---|---|---|
| `camb.get_results` (transfer + linear P, 150 z) | 0.39 s | 0.29 s | 0.37 s |
| `get_nonlinear_matter_power_spectrum()` (HMcode/halofit on 150 z) | **4.2 s** | **3.3 s** | 0.30 s |
| `get_sigma8`, `get_sigmaR` | ~0 | ~0 | ~0 |
| `sigma8toAs` auxiliary call (kmax 1.2, 1 z, no non-linear) | 0.06-0.15 s | | |

So the non-linear step (HMcode) over 150 redshifts, not the Boltzmann transfer, is ~90 % of the CAMB cost, and the auxiliary `sigma8toAs` run is only ~2 % of it. The estimates in items 1-3 below are revised accordingly.

1. **Remove the auxiliary CAMB run (`sigma8toAs`) by exploiting P_lin proportional to A_s.** Run one reference linear-spectrum computation per cosmology (omch2, ombh2, h0, n_s, mnu, ...) at a fixed A_s, then rescale the linear P(k,z) by `(S8_target-derived sigma_8 / sigma_8_ref)^2`, which is exactly the relation the module already uses (`A_s = A_fid (sigma_8_in / sigma_8_fid)^2`). The final run then needs only the non-linear correction for the rescaled linear spectrum. **[corrected after measurement]** Expected saving: the auxiliary run measured 0.06-0.15 s versus ~4.6 s for the main CAMB call (+HMcode), i.e. ~2 % of a likelihood evaluation for the S_8-sampled K1000 setup (the original 20-40 % estimate was wrong); none for the ln A_s KV450 fiducial. It is a clean-up, not a speed-up.
2. **Re-implement the non-linear step in numpy/numba and cache the linear transfer function per cosmology.** For HMcode only P_lin(k,z), sigma(R) and growth are needed; one CAMB call per (omch2, ombh2, h0, n_s, mnu) point, then rescale for A_s/S8. This also makes the A-dependence of HMcode (A_baryon, eta0) a cheap re-evaluation. Expected: a further 2-5x on evaluations where only baryon/IA/nuisance parameters change. **[revised after measurement]** because HMcode on 150 redshifts costs 3-4 s versus 0.3-0.4 s for the transfer step, this item (a vectorised/numba HMcode, and/or evaluating the non-linear P only on a coarser z grid of ~30-50 nodes inside the support of the lensing kernels and interpolating in z - an accuracy trade-off that must be validated against the 150-z result) is the dominant lever: up to ~10x on the CAMB module alone, and it applies to every evaluation, not only the ones where baryon/IA/nuisance parameters change. [estimate, not validated]
3. **Exploit the fast/slow hierarchy explicitly.** Order of expense: CAMB (cosmology: 5 params) >> Limber projection (depends on kernel, so on n(z) shifts delta z_i and A_IA) > Hankel transform > likelihood. Of the 14 KV450 parameters, 8 (A_IA, delta c, A_c, 5 delta z) never touch CAMB. **[corrected]** the original text counted 9 and included A_baryon, but `halo_model_parameters/A` and `eta0` are read inside the `camb` module (`camb_interface.py:225-233`), so A_baryon is a *slow* parameter in the CosmoSIS sense even when CAMB ignores it (mead2020). With the CosmoSIS `fast_slow` cache (`pipeline.py:97-316`) or an own cache of (P_lin, P_nl) keyed on the 5 cosmology parameters plus A_baryon, a sampler that makes oversampled fast moves (metropolis `oversampling` 5, PolyChord `fast_fraction` 0.3-0.5) re-evaluates only the cheap part: plausible 3-10x reduction of wall time per accepted sample. Only used in `KV450_no_sys.ini` and `BOSS_only.ini` today [corrected].
4. **Cheaper projection for nuisance moves.** C_ell^{ij} = integral over chi of W_i(chi) W_j(chi) / chi^2 * P(k=(ell+1/2)/chi, z(chi)) dchi (the Limber integral). P_nl(k_ell(chi), z(chi)) on the (ell, chi) grid depends only on cosmology; changing delta z_i or the IA kernel only changes the weights W_i. Precompute `P_nl` on the (ell, chi) grid once per cosmology and do a matrix contraction (`einsum`) with the 5 kernels; with the "fast IA" kernel `F = W - A (...)` this is 15 contractions per likelihood. Expected 5-20x on the projection module (I am stating the structure; actual timings unknown).
5. **Trim the transform grids.** 400 ell points up to ell_max = 5e5 (KV450) and a 1024-point Hankel transform per bin pair (15) is far finer than the 9 (or 13 after cuts) binned data points per pair require. Alternatives: FFTLog-based Hankel transform of all 15 pairs at once (vectorised in numpy), or a direct Bessel-kernel quadrature for the 9 bin-averaged angular windows using precomputed weights (`xi_bin = sum_ell C_ell * w_bin(ell)`, w precomputed once because the bin-averaging window in ell does not depend on cosmology). The latter removes the Hankel step from the sampling loop entirely (matrix-vector product 195 x n_ell). Expected 5-50x on that module.
6. **Turn off needless likelihood overhead** (`keep_theory_vector=F` during sampling; no `np.random.multivariate_normal` per call; use `scipy.linalg.cho_solve` on a pre-factored covariance instead of an explicit inverse, write the vector only for the final best-fit). Saves ~1-5 ms per call (a small fraction vs CAMB, but free).
7. **Better sampler configuration instead of brute force.** (a) Use a one-off MAP + Hessian (or short pilot chain) as the proposal covariance for metropolis/emcee (`covmat=`); with a good covariance an adaptive Metropolis with 14 parameters typically needs O(10^4-10^5) evaluations to deliver ~10^3 effective samples, versus the 1.4x10^5 evaluations quoted for the "quick" MultiNest run that yields ~9k "independent" samples. (b) For a gradient-capable re-implementation (JAX or numba-differentiable pieces), HMC/NUTS in the decorrelated parameter space (use the Cholesky parameters p_i for n(z) shifts) typically reduces the number of likelihood evaluations by 1-2 orders of magnitude versus nested sampling for unimodal posteriors like this one. (c) Replace Nelder-Mead MAP by L-BFGS-B or Newton on the analytic posterior once gradients are available; starting from the posterior mean/MAP of a short chain removes the need for 36 random starts.
8. **Parallelism.** CosmoSIS MPI evaluates independent live points / walkers per rank, but each rank re-reads module data and holds its own datablock. A threaded numpy/numba pipeline with shared read-only data (n(z), covariance, cuts) and vectorised batch evaluation (emcee `vectorize=True`, PolyChord/ultranest batches) avoids per-process duplication and the datablock copy overhead (copying P(k,z) 3-5 times per evaluation); estimated 1.2-2x on a many-core node for equal core counts.
9. **Emulation.** A neural or Gaussian-process emulator of the 195-element theory vector trained on the 5 cosmology + A_baryon + A_IA parameters (nuisance enter near-linearly) can reduce an evaluation from seconds to sub-millisecond, at the cost of validating emulator error against the 195x195 covariance (should stay << 0.1 sigma per element). Speed-up 10^2-10^4 on top of items 1-5, but must be validated against the exact pipeline.
10. **Post-processing.** `find_projected_joint_HPDI` recomputes `compute_sample_range_and_coverage` over an ever-growing index set and builds boolean masks over all N samples for each n (O(N^2)); a single pass with a running min/max over the sorted joint-posterior order plus a sorted-CDF lookup (searchsorted on cumulative weights) is O(N log N): expected 100-1000x for N ~ 10^5 samples and ~10-20 parameters.
